## 아핀 변환

아핀 공간(Affine space)
벡터 공간에서 이동 변환을 위해 벡터의 마지막 차원 값을 1로 한정한 부분 공간

2차원 벡터 공간에서 $x$대한 이동을 구현하고자 한다면, 다음과 같은 전단 변환 행렬 및 $y=1$로 고정된 벡터를 사용할 수 있다.
$$\begin{bmatrix}
  1 & a \\ 0 & 1
\end{bmatrix}
\begin{bmatrix}
  x \\ 1
\end{bmatrix}=
\begin{bmatrix}
  x+a \\ 1
\end{bmatrix}
$$
벡터의 $y$값은 변하지 않고, $x$값 만이 행렬에 명시된 전단값 만큼 이동되는 결과를 얻을 수 있다.

마찬가지로 2차원 이동 구현을 위해서는, 3차원 벡터 공간에서 마지막 요소 $z=1$로 고정한 부분 공간의 벡터를 사용하며, 회전 행렬 또한 세 번째 열벡터의 값을 통해 공간을 평행육면체 형태로 변형시킨다.
이때 위의 예시와 같이 전단 행렬이 변화시키는 3차원 공간 그 자체가 아닌 2차원 일부 요소만을 사용하는 것.

이렇듯 구하고자 하는 차원의 평행이동을 위해 한 차원 높여 설계하는 선형 변환을 아핀 변환 이라고 한다.
아핀 변환의 결과는 항상 아핀 공간 내 벡터가 되어야 한다. 즉 마지막 요소의 값이 1로, 닫혀있어야 한다.

### 변위 벡터(Displacement vector)
아핀 공간 내에 속한 원소들, 예를 들어 2차원 아핀 공간 내의 원소는 $(x,y,1)$ 꼴을 띄며, 이를 점(dot)이라고 한다. 물리적으로 존재한다는 의미를 내포함.
점을 이동시킬 경우, 점에 점을 더하는 것이 아닌, 순수하게 이동의 크기만을 가진, 즉 마지막 요소가 0인 벡터를 점에 더해야 한다. $z=1$ 로 유지시켜 아핀 공간에 닫혀있는 성질을 유지하기 위함으로, 이러한 벡터를 특별히 변위 벡터라고 칭한다.
즉 점끼리의 합 연산은 성립하지 않는다. 다만 점끼리의 차는 변위벡터가 되어, 한 점에서 다른 점까지 이동하기 위한 양을 나타내게 된다.

### 아핀 결합과 직선의 방정식
점들의 마지막 요소의 총 합이 1임이 보장이 된다면, 여러 점을 합하여 새로운 점을 만드는게 가능하다. 이를 아핀 결합 이라고 한다.
이 방식으로 두 점을 결합할 경우, 각 점에 서로 합했을 때 1이 되도록 $a,(1-a)$을 곱하여 수식을 만들 수 있다.
$$(1-a)P_1+aP_2=P'$$
두 벡터가 서로 1의 비율을 가지도록 하고 더하는 연산으로, 도출되는 모든 점들은 두 점 사이를 지나는 직선 위에 놓인다.
위의 식을 다음과 같이 정리하여 증명 가능하다.
$$a(P_2-P_1)=P'-P_1$$
이 수식을 직선의 방정식이라고 하며, 한 점에 다른 점으로 향하는 벡터를 더하는 방식으로 구하는 일반적인 직선의 방정식과 완전히 동일하다.
$$P_1+a(P_2-P_1)=P'$$


## 화면에 직선 그리기
화면에 직선을 그리는 과정은 다음 과정을 거친다.
1. 선의 시작점과 끝점 좌표가 정해진다.
2. 좌표평면 위 렌더링 할 영역이 정해진다.
3. 두 점을 이은 선이 영역 밖에 있다면 렌더링 생략, 영역을 지나친다면 잘라낸다. (클리핑)
4. 클리핑된 좌표를 스크린 좌표계의 좌표로 변환한다
5. 픽셀을 하나씩 칠하며 두 좌표 사이를 잇는다. (렌더링)

### 코헨-서덜랜드 라인 클리핑(Cohen-Sutherland)

영역의 중심 좌표와 너비, 높이를 통해 렌더링 영역을 정의할 수 있다.

점과 렌더링 영역의 상대적 위치에 따라 해당 점에 일종의 비트 플래그 값을 부여한다.
$y,x$플래그 순으로, 영역의 좌표보다 크면 $10$, 작으면 $01$, 아니면(범위 내)$00$ 로 총 4비트 부여
영역 내에 드는 점은 $0000$플래그 값을 얻게 된다.

두 점의 플래그값을 AND연산 하는 것으로 어느 정도 그릴 선과 그리지 않을 선을 생략할 수 있는 이점이 있다.
두 점의 AND 연산 결과가 0 이 아니라면 생략.
두 점이 (0000을 제외한)동일한 플래그 값을 가지면 또한 AND결과가 0이 아니므로 생략

알고리즘에서는 다음을 반복한다.(최대 3회)
- 두 플래그 값이 모두 $0000$이라면, 둘다 범위 내에 드므로 라인을 그린다.
- 두 플래그의 AND 연산 결과가 0이 아니라면, 확실히 범위를 벗어나므로 생략한다.
- 나머지 경우(둘 다 0000은 아니나 AND 결과가 0이다.) 영역 위를 지나거나, 예외 상황이므로 클리핑한다.
- 시작 또는 끝점을 클리핑 하고 위 조건을 다시 확인한다.

클리핑 시에는 직선의 방정식을 활용한다.
렌더링 영역의 좌우 또는 상하 구간을 나누어 구간 내 좌표의 클리핑 좌표 중 하나의 값을 렌더링 경계값으로 지정,
이후 해당 경계값을 직선의 방정식에 대입한다.

### 스크린 좌표계 변환
스크린 좌표계는 $(0,0)$부터 시작하여 우측이 $x$, 아래가$y$ 방향이고, $(W,H)$ 까지의 한정된 범위를 가지며, 모든 좌표가 정수값을 가진다. 
일반 좌표계 위에서 렌더링 할 영역을 정했다면, 그 위의 점이 그대로 스크린 좌표계 범위에 들도록 평행이동을 시켜주면 된다.
일종의 선형 변환 및 평행 이동 과정이라고 볼 수 있다.

두 렌더링 영역의 좌표가 $(x_{min},y_{min}),(x_{max},y_{max})$이고,
스크린 좌표계의 가로 세로 길이가 $W,H$일 경우,
렌더링 영역의 가로 세로 길이는
$$W_r=x_{max}-x_{min},\;H_r=y_{max}-y_{min}$$ 
이때 변환된 좌표는 최대한 풀어 쓰자면 다음과 같이 계산된다.

$$
\begin{bmatrix}
  x_{screen}\\y_{screen}\\1
\end{bmatrix}
=
\begin{bmatrix}
1&0&W \\ 0&1&0 \\ 0&0&1  
\end{bmatrix}
\begin{bmatrix}
1&0&0 \\ 0&-1&0 \\ 0&0&1  
\end{bmatrix}
\begin{bmatrix}
W/W_r&0&0 \\ 0&H/H_r&0 \\ 0&0&1  
\end{bmatrix}
\begin{bmatrix}
1&0&-x_{max} \\ 0&1&-y_{max} \\ 0&0&1  
\end{bmatrix}
\begin{bmatrix}
  x\\y\\1
\end{bmatrix}$$
$$(x_{screen},\;y_{screen})=(\frac{W}{W_r}(x-x_{max})+W,\;\frac{-H}{H_r}(y-y_{max}))$$

스크린 영역은 1사분면에 위치하며, $+y$ 방향이 아래이므로,
우선 렌더링 최대 좌표 우상단을 원점에 맞추어 렌더링 영역이 3사분면에 오도록 평행이동하고,
스크린 영역의 크기와 동일해지도록 크기를 조절하고,
$y$좌표를 뒤집음과 동시에 2사분면에 배치, 그대로 $x$축 방향으로 평행이동 시킨다.

이후 소수점 아래를 날려 정수값만이 남도록 해준다.

### 브레젠험 알고리즘
정수로 표현된 두 좌표 사이를 잇는 픽셀의 정수 좌표를 도출하는 방법
$45\degree$선의 경우 한 픽셀의 다음 픽셀은 언제나 $x$방향으로 $\pm1$, $y$방향으로 $\pm1$만큼 즉 대각선 방향의 픽셀이 된다.
만약 두 좌표 사이 그려질 선의 기울기의 절댓값이 $45\degree$ 보다 작을 경우,
한 픽셀의 다음 $x$좌표값은 $\pm1$, 반면에 $y$좌표값는 $\pm1$이 될지 안될지 따로 비교하여 결정해 줘야 한다.
마찬가지로 기울기의 절댓값이 $45\degree$ 보다 클 경우,
한 픽셀의 다음 $y$좌표값은 $\pm1$, 반면에 $x$좌표값는 $\pm1$이 될지 안될지 결정해 줘야 한다.
(모두 합하면 8가지 경우가 나온다)

이것을 결정하는데에는 직선의 방정식에서 유래한 판별식이 쓰인다.
두 점을 지나는 직선의 방정식
$$w={x_1-x_0},\;h={y_1-y_0} \\\;\\ y=\frac{h}{w}x+y_0-\frac{h}{w}x_0 \;\;\text{or}\;\; x=\frac{w}{h}y+x_0-\frac{w}{h}x_0$$

여기서 픽셀의 $y$좌표값을 비교할 경우 첫번째 식을 사용한다.
픽셀의 정수 좌표를 픽셀의 중심점이라고 하자.
이때 어떤 픽셀의 $x$에서의 방정식의 $y$값이,
해당 픽셀과, 비교 대상이 되는 픽셀의 중간 지점의 $y$보다 작을 경우 픽셀을 1칸 내린다.
클 경우, 픽셀의 $y$값에 영향을 주지 않는다.

픽셀의 $y$가 올라가거나 내려간 정도를 $m$이라 하고,
픽셀의 $x$가 진행된 정도를 $n$이라고 하면, 
$$
\begin{aligned}
\frac{h}{w}x+y_0-\frac{h}{w}x_0 &< y_0+(m\pm0.5)\\
h(x-x_0)-w(m\pm0.5) &< 0\\
2h(x-x_0)-w(2m\pm1) &< 0\;\;\;(x=x_0+n)\\
h(2n)-w(2m\pm1) &< 0
\end{aligned}
$$
비교 대상이 되는 픽셀은 감소하는 직선의 경우 아래에 존재하므로 $+1$을, 증가하는 경우 $-1$을 적용한다.
만약 첫 픽셀에서 3번째 다음칸의 픽셀에 판별식을 적용하는데, 이미 1 픽셀이 내려간 상황이라면,
$n=3, m=1,\; 6h-3<0$ 을 검사하면 된다.
$n,m$은 서로 비례하지 않고 독립적으로 진행된다.
직선이 $-x$방향으로 진행된다면, $n$은 음수값을 가지게 된다.
직선이 감소한다면, $m$은 0에서부터 점차 감소하며 음수값을 가진다.

원래라면 직선의 방정식 및 픽셀 중간점을 활용하므로 실수 연산이 필요한 것처럼 보이지만, 최종 정리된 부등식이 간단한 정수 값만을 활용한다는 점 또한 최적화적으로 이점이 있다.

시작점과 끝 점을 바꾸어 반대 방향으로 그릴 경우, 결국 비교의 기준점이 두 픽셀의 중간 지점이 되는 것은 변하지 않으므로, 동일한 직선이 그려진다.

픽셀 좌표를 픽셀의 중간 지점이 아닌, 픽셀 그리드의 교차점으로 잡는 경우, 직선과 비교 기준점을 모두 $-(0.5,0.5)$ 씩 평행 이동 한 것과 같다.
비교 기준점까지 옮겼으니, 부등식의 결과도 항상 동일하다.
비교 대상인 두 픽셀이 바뀌는 것도 아니다. 따라서 결과에는 변함이 없다.
(근본적으로 두 방식에 차이가 없기도 하다)

## 직선 그리기 의사코드
위 모든 과정을 간단한 의사코드로 나타내면 다음과 같다.
```cpp
// 시작점과 끝점의 좌표
vec2 start;
vec2 end;

// 렌더링 영역의 시작점과 끝점의 좌표
vec2 renderMin;
vec2 renderMax;

// 입력된 pos의 영역 플래그 값을 반환하는 함수
int regionTest(vec2 pos, vec2 min, vec2 max){
  int result = 0b0000;
  // x영역 판정
  if (pos.x < min.x) result |= 0b0001;
  else if (pos.x > max.x) result |= 0b0010;
  // y영역 판정
  if (pos.y < min.y) result |= 0b0100;
  else if (pos.y > max.y) result |= 0b1000;

  return result;
}

// 시작점과 끝점의 테스트 값
int startTest = regionTest(start, renderMin, renderMax);
int endTest = regionTest(end, renderMin, renderMax);

// 클리핑 시 직선의 방정식에 사용할 너비, 높이값
float w = end.x - start.x;
float h = end.y - start.y;

// 1. 모두 영역에 들어서 바로 그리거나
// 2. start만 클리핑 후 그리거나
// 3. end만 클리핑 후 그리거나
// 4. start, end 모두 클리핑 후 그리거나
// 5. 모두 절대 그려질 수 없어 바로 취소하거나
// 6. start쪽을 클리핑 했을 때 범위를 벗어나 취소되거나
while(true){
  if (startTest == 0b0000 == endTest) break; // 둘 다 영역에 들면, 그리면 된다.
  else if (startTest & endTest) return; // 0이 아니라면, 절대 영역에 들지 않기에 취소한다.
  else { // and 결과는 0이지만, 둘 다 혹은 둘 중 하나가 0이 아닌 경우 -> 클리핑
    vec2 clipped; // 클리핑된 좌표
    // 시작점을 먼저 클리핑 한다.
    int curTest = startTest != 0b0000 ? startTest : endTest;

    // 영역 기준 좌 우 두 구간에 있을 경우
    if (curTest < 0b0100){
      // 왼쪽에 있을 경우 min x값으로
      if (curTest & 0b0001) clipped.x = renderMin.x;
      // 오른쪽에 있을 경우 max x값으로
      else clipped.x = renderMax.x;
      // f(x)방정식에 클리핑된 x값 대입
      clipped.y = start.y + h*(clipped.x-start.x)/w;
    }
    // 영역 기준 상 하 여섯 구간에 있을 경우
    else{
      // 아래쪽
      if (curTest & 0b0100) clipped.y = renderMin.y;
      // 위쪽
      else clipped.y = renderMax.y;
      // f(y)방정식에 클리핑된 y값 대입
      clipped.x = start.x + w*(clipped.y-start.y)/h;
    }
    if(startTest){
      start = clipped;
      startTest = regionTest(start, renderMin, renderMax); // 다시 테스트
    }
    else{
      end = clipped;
      endTest = regionTest(end, renderMin, renderMax);
    }
  }
}

// 스크린 좌표계의 크기
int Ws = 600;
int Hs = 300;

// 렌더링 영역의 크기
float Wr = renderMax.x - renderMin.x;
float Hr = renderMax.y - renderMin.y;

// 스크린 좌표계로 변환
vec2Int startS = {Ws/Wr(start.x - renderMax.x)+Ws, -Hs/Hr(start.y-renderMax.y)};
vec2Int endS = {Ws/Wr(end.x - renderMax.x)+Ws, -Hs/Hr(end.y-renderMax.y)};

// 스크린 좌표 상 두 점간의 너비, 높이값
int W = endS.x - startS.x;
int H = endS.y - startS.y;

bool isGradual = abs(W) >= abs(H); // 기울기의 절댓값이 45도 이하라면 true가 된다.
int dx = W >= 0 ? 1 : -1; // 선이 왼쪽에서 오른쪽으로 진행된다면, 언제나 x는 1씩 증가한다
int dy = H > 0 ? 1 : -1; // 선이 아래에서 위로 진행된다면, 언제나 y는 1씩 증가한다
int fw = dx * W; // 판별식 설계용
int fh = dy * H; // 판별식 설계용

int f = isGradual ? fh*2 - fw : fW*2 - fh; // 기울기에 따른 기본 판별식 결정
int f1 = isGradual ? fh*2 : fw*2; // 높이 변화 없이 진행될 경우 판별식 증감값
int f2 = isGradual ? 2*(fh-fw) : 2*(fw-fh); // 높이 변화 있을 때 판별식 증감값

int x = startS.x;
int y = startS.y;

if (isGradual){ // 45도 이하
  while(x != endS.x){
    SetPixel(x, y); // 우선은 현 좌표를 먼저 칠한다.
    if (f < 0) f += f1; // 높이 변화 없음
    else { // 높이 변화 발생
      f += f2;
      y += dy; // y변화
    }
    x += dx;
  }
  SetPixel(x, y); // while 조건에서 마지막 픽셀은 칠하지 않기 때문에 마지막에 따로 처리
}
else{ // 45도 초과, 로직은 위와 동일함
  while(y != endS.y){
    SetPixel(x, y);
    if (f < 0) f += f1;
    else {
      f += f2;
      x += dx;
    }
    y += dy;
  }
  SetPixel(x, y);
}
```
